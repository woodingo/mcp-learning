# Упаковка проекта для передачи другому члену команды

## Контекст

Проект MCP-сервера для корпоративного трекера задач. Нужно подготовить его так, чтобы другой разработчик мог склонировать, настроить свои credentials и запустить без секретов инициатора.

Текущее состояние:
- `.env` в `.gitignore` — секреты не попадают в git ✓
- `.env.example` существует с плейсхолдерами ✓
- В исходном коде нет захардкоженных паролей ✓
- `express` не в `package.json` (транзитивная зависимость SDK) — ненадёжно
- `mcp-server.service` хардкодит пути `/home/woody/...`
- Нет `README.md`
- `TRACKER_USER_ID` отсутствует в таблице переменных `docs/development.md`

## План

### 1. Добавить `express` в `package.json`

Файл: `package.json`

Добавить `"express": "^5.2.1"` в `dependencies` (версия совпадает с текущей транзитивной). Express используется в `src/http.ts` напрямую, рискованно полагаться на транзитивную зависимость.

### 2. Создать `README.md`

Файл: `README.md` (новый)

Содержимое — краткий quick-start:
- Что это (MCP-сервер для трекера задач)
- Предварительные требования (Node.js v22+)
- Установка: `git clone` → `npm install` → `cp .env.example .env` → заполнить `.env`
- Запуск: `npm run build && npm start` (stdio) / `npm run start:http` (HTTP)
- Ссылки на документацию в `docs/`

### 3. Шаблонизировать `mcp-server.service`

Файл: `mcp-server.service`

Заменить хардкод `/home/woody/...` на плейсхолдеры `<USER>` и `<PROJECT_DIR>`, добавить комментарий в начале файла с инструкцией по замене. Убрать специфичный nvm-путь к node — использовать `/usr/bin/node` (通用).

### 4. Обновить `docs/development.md`

Файл: `docs/development.md`

Добавить `TRACKER_USER_ID` в таблицу переменных окружения (секция "Общие").

### 5. Обновить `docs/systemd-service.md`

Файл: `docs/systemd-service.md`

Привести пример service-файла в соответствие с обновлённым шаблоном (плейсхолдеры вместо хардкода).

## Затронутые файлы

| Файл | Действие |
|------|----------|
| `package.json` | Добавить express в dependencies |
| `README.md` | Создать (новый файл) |
| `mcp-server.service` | Шаблонизировать пути |
| `docs/development.md` | Добавить TRACKER_USER_ID в таблицу |
| `docs/systemd-service.md` | Обновить пример service-файла |

## Валидация

1. `npm install` — проверить, что express установился
2. `npm run build` — компиляция без ошибок
3. Проверить, что `.env` не содержит реальных секретов (в git не попадает)
4. Прочитать `README.md` глазами получателя — понятно ли что делать

## Риски

- **minimatch**: обновление express может привнести новые транзитивные зависимости — нужно проверить `npm ls` после установки
- **Совместимость**: Express 5 может отличаться от той версии, что сейчас используется транзитивно — нужно проверить, что `http.ts` компилируется
